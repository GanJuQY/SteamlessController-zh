## 改一版怎么发

1. 本地先验证补丁还能打、还能编：

   ```bash
   bash scripts/mingw-build.sh          # WORK= 可覆盖工作目录
   sha256sum "$WORK/out/SteamlessController.exe"   # 记下校验值
   ```

2. 提交信息写清**实际改了什么**，建议前缀 `feat:` / `fix:` / `docs:` / `chore:`，
   别用「更新」「优化」这类空话（例如：`fix: GetHtml() 按 UTF-8 解码，中文界面不再乱码`）。
3. 推送：`git push origin main`。
4. 打 tag 并建 Release：tag 用 `zh-vN`（带 `zh` 前缀，示意这是第三方汉化，别蹭上游版本号），
   说明用 `RELEASE_NOTES.md`，附件是重新打包的 zip。
5. CI 会自动跑一遍 `scripts/mingw-build.sh`（见下），绿了说明补丁仍然干净。

## 打包（zip 必须带 UTF-8 文件名标志）

Info-ZIP 的 `zip -r` 不写 UTF-8 文件名标志，Windows 上解开会乱码。用 Python 的 `zipfile`
逐条 `write(路径, 归档名)` 重建：

```bash
python3 - <<'PY'
import zipfile
names = ["SteamlessController.exe", "WebView2Loader.dll", "安装说明.md"]
with zipfile.ZipFile("SteamlessController-zh-v2.zip", "w",
                     zipfile.ZIP_DEFLATED, compresslevel=9) as z:
    for n in names:
        z.write(n, n)
PY
```

## 凭据

这台机器上**没有** `gh`、没有登记过的 SSH key；HTTPS 推送由 `dsh-git-forge` 装的
credential helper 提供 token（数据在 `~/.dsh/git-forge/`，文件权限 0600，位于仓库之外，
**不在仓库、不进文档**）。要在别的机器上操作，用 `gh auth login`、SSH key 或 PAT 三选一即可。

注意：PAT 需要 `repo` 权限；若要推送 `.github/workflows/` 下的工作流文件，还需要 `workflow` 权限
（本仓库因此把 CI 定义放在 `ci/build.yml`）。

## CI

CI 定义放在 **`ci/build.yml`**，不是 `.github/workflows/`：GitHub 拒绝用不带 `workflow` 权限的 token
创建或更新工作流文件（推送时会报
`refusing to allow a Personal Access Token to create or update workflow ... without 'workflow' scope`）。

启用方式二选一：

- **网页上启用（最快）**：在 GitHub 网页里新建文件 `.github/workflows/build.yml`，把 `ci/build.yml` 的内容粘进去再提交；
- **命令行启用**：把推送用的 token 重新签发时勾上 `workflow` 权限，然后
  `git mv ci/build.yml .github/workflows/build.yml && git commit -m "chore: 启用 CI" && git push`。

启用后它在每次 push 时用 ubuntu-latest 跑一遍 `scripts/mingw-build.sh`（拉上游 main → 打三个补丁 →
MinGW 交叉编译），把 exe / dll 作为 artifact 传上去，并打印 sha256。**这等于每次提交都验证一遍补丁还能打、还能编。**
脚本里带了 `-Wl,--no-insert-timestamp`，所以 CI 编出来的 exe 与 Release 里的应当字节一致。

## 建议顺手做的一件事：把汉化交回上游

上游是 MIT，作者接受 PR 的话就不必长期维护分支了。可以直接开 issue 贴这段：

> Hi! I made an unofficial Simplified Chinese localisation of SteamlessController and would like to
> offer it back upstream. Two things are in it:
>
> 1. **A UTF-8 bug that only shows up with non-ASCII UI text.** `RemapWindow::GetHtml()` widens the
>    embedded HTML one byte per `wchar_t` (`w += static_cast<wchar_t>(static_cast<unsigned char>(*p))`),
>    which is fine while the page is ASCII-only, but turns any multi-byte character into two or three
>    mojibake glyphs. Fix is 3 lines using `MultiByteToWideChar(CP_UTF8, ...)` — same conversion your
>    `LauncherGames.cpp` / `SteamAppLocator.cpp` already use.
> 2. The translation itself (~1300 Chinese characters: tray menu, menus, balloons, dialogs, and the
>    whole embedded page).
>
> Happy to send it as a PR, or as two separate PRs (bug fix first, translation second) if you'd rather
> review them independently. If you'd prefer not to carry translations in-tree, no problem — I'll keep
> it as a fork.
